Sales forecasting and pipeline management get used like synonyms.

They're not. They answer two different questions, for two different
audiences.

Mixing them up is why a bad forecast so often gets treated as a
modeling problem, when the actual break happened somewhere else
entirely.

## Two different questions

Pipeline management is deal-level. It asks: what's actually true
about this specific opportunity, right now?

Is it in the stage it claims to be in? Does the rep still believe it
closes this quarter, or are they carrying it out of habit?

Forecasting is aggregate. It asks a completely different question:
across every open deal, what dollar amount closes by the end of the
period?

One is a read on a single deal. The other is a rollup across all of
them.

## Where the confusion comes from

Forecasting is *built out of* pipeline data — stage, probability,
close date, deal size.

That makes the two feel like one continuous system. In practice
they're two separate jobs with two separate owners.

| | Pipeline management | Forecasting |
|---|---|---|
| Question it answers | What's actually happening in this deal | What closes, in total, this period |
| Owned by | The rep, deal by deal | Leadership, reading the rollup |
| Input | The rep's real-time judgment | Every rep's stage and probability data |
| Breaks when | A rep stops updating a deal's real status | The inputs feeding it were already wrong |

The forecast doesn't generate its own information. It inherits
whatever the pipeline already recorded — accurate or not.

## The direction the errors actually flow

[Sales forecasting techniques](/blog/sales-forecasting-techniques)
tend to focus on the model: better weighting, more history, smarter
averaging across reps.

None of that fixes a bad forecast whose real problem started
upstream. If a rep leaves a deal at 70% probability three weeks after
they privately gave up on it, no amount of model tuning recovers the
truth that was never entered.

[Forecast by rep](/blog/forecast-by-rep) is where this shows up
first — not in the topline number, but in the gap between what one
rep's pipeline says and what that rep would actually tell you,
off the record, about the same set of deals.

## Fixing the model fixes the wrong end

A forecasting model can only average what it's given.

Tune it all you want. If the pipeline stage data going in is
optimistic, the forecast coming out will be optimistic in exactly the
same proportion — just wrapped in a more sophisticated-looking
number.

[Pipeline forecasting](/blog/pipeline-forecasting) gets more accurate
the same way [sales pipeline health](/blog/sales-pipeline-health)
does: by asking the rep, privately, before the number goes anywhere
public, which deal they'd actually downgrade.

That's a pipeline-management fix. It happens upstream of the model,
not inside it.

## Two jobs, one number

Pipeline management and forecasting are separate work, done by
different people, at different points in the deal.

Treat the forecast as broken and you'll go tune a model. Treat the
pipeline as the actual source, and you'll go ask a rep an honest
question instead.

Only one of those fixes the number.
